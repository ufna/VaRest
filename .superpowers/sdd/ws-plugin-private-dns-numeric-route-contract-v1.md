## Actual cause and available boundary

Current `FConn::Start`193-257 calls ordinary `lws_client_connect_via_info` on the service thread. Private `client-handshake.c`205-249 chooses HTTP proxy, optional SOCKS, then direct origin and calls `getaddrinfo`; changing only `Info.address` cannot remove proxy DNS. Original Host/TLS identity comes from other headers, and must remain separate from the physical TCP tuple. `FService::Shutdown`1380-1414 ultimately calls `Kill(true)` on that same service thread: it can therefore wait in OS DNS. The existing tracked numeric/local route is restricted to its actual native custody/budget/loopback premises; it is NOT a general substitute and remains off.

Actual ordinary `ModuleManager.cpp`1346-1381 calls ShutdownModule/deletes the interface but skips physical DLL unloading for `bIsShutdown`. Dynamic unload1317 may unload code independently of the module's SupportsDynamicReloading declaration; the callback helper1989 instead abandons unsupported modules. Current WS declares SupportsDynamicReloading=false. These are bounded source observations, not a current global-exit/ownership or arbitrary-provider guarantee. The worker must never borrow a module-interface, service, connection, context, UObject, Core allocator object, callback, ticker or UE TLS object after their lifetime.

## Native resolver storage and execution

Use a new source-private Linuxx64 backend in VaRestWebSocket, independent of old owner-role ABI entrypoints. Do not call NativeSubmit2 without its real role or fabricate an old owner/session/plan. Allocate one native POD pool per loaded module image, lazily, with a fixed32-slot admission limit. Allocation uses libc-owned storage; no UObject/TArray/FString/UE allocator or callback crosses into the worker. Each slot contains copied counted ASCII hostname/decimal port input, generation/interest atomics, actual pthread handle/result and native addrinfo ownership. Limit applies to running, canceled-unjoined, joined-unconsumed and poisoned slots; no hidden unbounded submission queue. Check empty/overlong/NUL host, port, nonwrapping generation and allocator/pthread errors before issuing a ticket.

A real joinable pthread performs actual OS getaddrinfo with AF_UNSPEC/SOCK_STREAM/AI_NUMERICSERV. It publishes status/list only in native storage; no UE call, service wake callback, DNS cache replacement or pthread_cancel/detach. Result publication is not thread retirement. Only actual pthread_tryjoin_np==0 permits result adoption, slot reinitialization or physical input reclamation; EBUSY retains ownership and other errors poison/retain rather than retry a possibly consumed handle. Logical cancel clears an atomic generation-tagged interest; it never frees/reuses live native storage. Concurrent late old-token discard cannot clear a new generation.

Preserve the genuine native addrinfo list after join and walk it incrementally, at most32 raw nodes per control turn, emitting one valid sockaddr at a time. This tries every usable OS-returned address until success, list end or the unchanged original connect deadline; it does not silently truncate to old ABI's eight-address array or requery DNS per candidate. No unbounded auxiliary address/dedup array; native resolver/list allocations and provider internals are outside a hard byte/RSS/time bound. Free the owned list only at a known joined release boundary. On close/timeout, the ticket may become an orphan owned by the pool, independent of the freed FConn.

Control calls use a native try-lock or equivalent bounded atomic protocol; a descheduled actor never causes another service/GT to block for its lock. Worker never needs that control lock. A module-owned cleanup ticker and normal service passes may poll retirement; the ticker is just a supported callback, not evidence of whole Tick return. Shutdown closes admission/discards interests and performs only bounded nonblocking retirement attempts. Unjoined/uncertain native state remains retained. Do not promise that OS DNS physically obeys ConnectTimeout, that every native thread has stopped when transport Shutdown returns, or that all native memory is released at module shutdown.

## Code lifetime and reload/fork

For modular Linux, establish exactly one process-lifetime own-image loader reference before the first worker: dladdr the hidden actual worker entry and reopen that already resident image with RTLD_NOLOAD and an ordinary local load mode. Fail before pthread_create if actual identity/ref acquisition is not established. Deliberately retain that reference and the trivial native pool until process exit; no worker releases its own last code handle. Monolithic code is the actual process image; do not try to dlopen an executable pathname or invent an equivalent modular handle. No per-request handle leak, no general linker-namespace isolation claim, no Core/module-manager override. Native job input/result/entry code and libc provider accesses remain valid while a job is unjoined; no UE dependency survives through a worker callback. This is explicit bounded-per-image retention, not a claim of physical unload or a process-wide bound across arbitrary unsupported hot-reloaded image versions.

The existing no-dynamic-reload policy remains. A logically stopped instance stays stopped; do not silently resurrect it after abandonment. Normal transport shutdown cancels only its interests and does not stop other transports' pool jobs. Module shutdown closes the pool once and unregisters its cleanup callback. Handle a changed PID after fork using a fresh child pool and never use/join inherited parent pthread handles. Do not create native workers in an unsafe pre-fork or not-yet-multithread child phase: use actual Fork helper state; defer admission under the original logical deadline until the supported child phase. Actual fork/server qualification remains a separate required gate; no synthetic bool or always-true child claim.

## Private C numeric route, proxy and TLS

Add explicitly named private numeric-route types/fields, not repurposed reserved/_unused cells or old custody permission bits. Paired private headers and the whole private C archive are rebuilt together. The default private FService context requires numeric routing; legacy/tracked contexts are not silently changed or treated as an authority grant. A new explicitly prefixed pure C helper selects the same effective vhost/HTTP-proxy/SOCKS/direct host and physical port as existing upstream source, without DNS or credentials in its output. The service copies that exact route hostname/port before worker submission. Do not duplicate proxy grammar in C++, resolve origin instead of proxy, or alter the configured proxy/credentials.

Copy a completed normalized numeric sockaddr plus resolved-for host/physical-port/route-kind into the new WSI before progressing connection. At the original physical-connect branch, validate it against the current actual effective route and construct sa46 directly with inet_pton/binary address data. No getaddrinfo/gethostbyname or nonnumeric fallback is reachable in numeric-only contexts, including a missing/mismatched route, redirect/reset or error continuation. Preserve existing socket options, poll membership, nonblocking connect, actual SO_ERROR handling, IPv4/v6 policy, HTTP CONNECT and SOCKS handshake. Original upstream peer name, original port, path, Host, Origin and TLS SNI/X509 name stay original; only TCP changes. Do not inject the numeric proxy address into TLS or CONNECT identity.

Reject redirects before any second DNS/TCP hop, preserving a truthful Redirect terminal result and actual HTTP status. Default legacy behavior is not proof that resetting a WSI retains a valid numeric route: clear/refuse stale numeric data on reset. Fix the concrete current IPv6 error-path source defect while touching this branch: result->ai_addr is initialized before checking failed getaddrinfo. No claim that the present optimized binary necessarily traps, and no whole upstream audit inferred.

## FConn/service state and deadlines

Store asynchronous state separately from dormant Native.Stage. Start captures original StartedAt/ConnectDeadline once before admission/resolution; pending admission/resolution participates in the existing short wait and NextDeadline calculation. A completion is consumed outside a library callback only if token/current owner still match, not canceled, service not stopping and the original deadline still has time. A timeout or close with no WSI must issue its one terminal event, drop interest, balance TLS count and become erasable; Kill's existing no-WSI early return alone is insufficient.

Hold at most one candidate/WSI episode. On a retryable pre-open connection failure, wait for actual WSI destruction or the existing verified drop boundary before clearing/reusing its fields, then consume the next native address. Do not reset original deadline, parallelize speculative sockets or retry certificate/redirect/upgrade/protocol refusals as successful fallbacks. Preserve callbacks, pending error precedence, kill/reap, close queues/credit, exactly-one terminal event and current scalar stats. No open/old WSI/context pointer can escape into a native DNS job. Keep the conservative SSL-index handshake rule while an actual library handshake can remain; canceled DNS with no WSI/SSL object may release logical TLS interest without claiming the native DNS worker joined.
